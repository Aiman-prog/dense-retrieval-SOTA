# Async Fast-GRASS Architecture

## Goal

Current Fast-GRASS runs mining, cache maintenance, and training in one sequential
optimizer loop:

```text
mine batch against H -> fresh loss encode -> optimizer step -> maybe maintain H
```

Async Fast-GRASS should keep the Fast-GRASS negative selection objective, but
move expensive mining onto a separate process in the ANCE style. The trainer
continues optimizing on the latest completed mined dataset while a miner prepares
the next one from a recent checkpoint.

This is ANCE-style only in process orchestration and handoff. It is not ANCE
mining:

```text
ANCE:             checkpoint -> full-corpus encode -> ANN index -> negatives
Async Fast-GRASS: checkpoint -> bounded cache H -> GRASS score -> negatives
```

Async Fast-GRASS must not rebuild a full-corpus ANN index during training, and
must not return to per-query stale FAISS top-P mining.

## Borrowed, Preserved, Deferred

Borrowed from ANCE:

```text
trainer and miner/inferencer run in parallel
trainer saves checkpoints at optimizer-step cadence
miner polls valid checkpoints
miner writes complete mined training data
trainer swaps to ready mined data without resetting optimizer state
```

Preserved from Fast-GRASS:

```text
bounded global cache H
stale cached document states for selection only
GRASS score g(q,d) = s_hat(q,d) + lambda * sigma(q,d)
fresh encode of query, positive, and selected negatives for the loss
miner-side cache refresh/replacement
```

Deferred future variant:

```text
async EMA Fast-GRASS
```

The first async implementation targets **cached-MCDP**. Each cache slot stores
`T` stochastic document embeddings produced together at its most recent
refresh. Query mining performs fresh stochastic query encodes but no document
encoder calls. The previous lazy fresh-MCDP top-`L` path is retained only as a
small-sample quality oracle, not as the production async miner.

EMA stays deferred unless checkpoints also save the EMA teacher. Rebuilding an
EMA teacher from student checkpoints in the miner is not equivalent to the
sequential EMA state.

## Main Processes

```text
train_async_fast_grass.py
    prepares initial Fast-GRASS mined data
    starts the miner as a background process on GPU 1
    runs the trainer independently on GPU 0
    terminates and waits for the miner after the trainer exits

run_async_fast_grass_train.py
    owns model gradients, optimizer, scheduler, checkpoints
    consumes mined JSONL files
    never mutates H, R, utility, or cached MC document states

run_async_fast_grass_miner.py
    owns H, R, Z_mc, Z_mean, cache utility, and cache age
    loads valid trainer checkpoints
    mines full JSONL training rounds
    refreshes/replaces H periodically during each mining round
    saves final cache_state_N at round end
```

The split is strict. The trainer owns gradient training only. The miner owns
selection state only.

## Handoff Layout

Use a Fast-GRASS-specific async work directory:

```text
temp_fast_grass_workdir/
  async_mining/
    initial_data/
      *.jsonl
    mining_meta_initial.json
    cache_state_initial.pt
    ready_initial

    work_N/
      training_data/
        *.jsonl
      cache_state.pt
      mining_meta.json

    training_data_N/
      *.jsonl

    cache_state_N.pt
    mining_meta_N.json
    ready_N
```

`ready_N` is the only trainer-visible completion signal. It must be written
after all JSONL files, `cache_state_N.pt`, and `mining_meta_N.json` are complete.
Publish `training_data_N/` by atomically renaming `work_N/training_data/`, then
atomically move the cache state and metadata to their final paths. Write
`ready_N` last through a temporary marker plus atomic rename. The trainer must
never read files from `work_N/`.

On restart, a mining round is committed only when its `ready_N` exists. The
miner loads the cache state for the newest committed ready round, never merely
the highest-numbered `cache_state_N.pt`; a crash may leave unpublished final-path
artifacts without a ready marker.

The initial data is generated by the same cached-MCDP miner path. Initialization
samples `B_doc` document IDs, encodes every sampled document for all `T` dropout
passes with the base model, computes `Z_mean`, and only then mines
`initial_data`. It is not ANCE mining and does not use per-query FAISS top-P.
Its metadata uses `source_checkpoint="base_model"` and
`source_checkpoint_step=0`.

## Step Vocabulary

Async Fast-GRASS should avoid epoch-based reasoning except when deriving
`max_steps`. The important units are:

```text
checkpoint_step
    trainer optimizer step whose checkpoint weights the miner uses

source_checkpoint_step
    checkpoint_step recorded in miner outputs and trainer logs

consume_step
    trainer optimizer step where a mined round becomes active

async_gap_steps
    consume_step - source_checkpoint_step

mining_round
    one complete mined dataset for the full training mixture
```

The trainer logs `source_checkpoint_step` for every active round. This makes the
model-data lag visible rather than hidden inside wall-clock behavior.

## Cadence, Self-Pacing, and Timing Calibration

`async_mine_every_steps` is a fixed configuration value, set ANCE-style. It is
the interval, in trainer optimizer steps, at which the trainer saves a
checkpoint. It is not a quantity the system computes or updates at runtime.

The pipeline paces itself through the handoff protocol, not through a computed
cadence:

```text
trainer saves checkpoints at the fixed async_mine_every_steps interval
miner, when it finishes a round, always picks the newest valid checkpoint
miner skips any older checkpoints between rounds
trainer swaps to the newest ready_N round and skips older ready rounds
if no new round is ready, the trainer keeps consuming the current one
```

Correctness never depends on the cadence being "right." If the miner falls
behind, the trainer reuses current data and `data_age_steps` grows; later
consumed rounds may also show larger `async_gap_steps`. If the trainer runs
ahead, the miner simply skips the intermediate checkpoints. The `ready_N`
markers + newest-ready selection + skip-stale checkpoints are the self-pacing
mechanism.

### Relationship to ANCE

ANCE uses a fixed refresh/checkpoint cadence (for example, refresh the ANN index
every m batches, or save a checkpoint every `save_steps`) with a fixed
Trainer:Inferencer GPU split. It does not dynamically compute the cadence from
measured trainer and miner throughput; the always-take-newest inferencer plus
the skip-stale trainer absorb any mismatch. Async Fast-GRASS follows the same
engineering pattern: a fixed checkpoint cadence plus a self-pacing handoff.

### Timing calibration (pre-run sanity check only)

Timing calibration is a pre-run diagnostic, not a runtime controller. Measure
trainer step time (`t_train_step`) and miner round time (`t_mine_round`) only to
choose an initial fixed `async_mine_every_steps`, roughly one checkpoint per round
the miner can consume (`~= ceil((t_mine_round / t_train_step) * safety_margin)`,
`safety_margin` 1.1-1.25). The real system self-paces through `ready_N` markers and
skip-stale behavior, so this value need not be exact; adjust it after the first run
from measured `async_gap_steps` and data reuse span. Detailed timing commands,
settings, and the cadence formula belong in `async_fast_grass_implementation_details.md`.

## Miner Round

At the start of a mining round:

```text
load newest valid checkpoint selected after the previous round finished
load cache_state from the previous round
set source_checkpoint_step from the checkpoint name
freeze model weights for the full round
```

The miner must not interrupt a round when a newer checkpoint appears. Once a
round starts, it finishes that round, publishes it, and only then picks the
newest valid checkpoint. Older checkpoints may be skipped.

For every virtual mining batch:

```text
encode queries T times with dropout and no gradients
score each query pass against the matching cached document pass over all H
compute per-pair score mean and population standard deviation
compute g(q,d) = s_hat(q,d) + lambda * sigma(q,d)
mask known positives
select m negatives
record selected slots/docids for utility accounting
write selected negatives into output JSONL records
append the query MC states to the bounded recertification reservoir
```

For query pass `t` and cache slot `d`:

```text
s_t(q,d)    = dot(q_t, Z_mc[t,d])
s_hat(q,d)  = mean_t(s_t(q,d))
sigma(q,d)  = sqrt(mean_t((s_t(q,d) - s_hat(q,d))^2))
g(q,d)      = s_hat(q,d) + lambda * sigma(q,d)
```

Use the population standard deviation (`correction=0`). `Z_mean` is retained for
diagnostics, compatibility, and cheap similarity probes; it must not replace
the `T` paired scores when calculating `sigma`.

There is no top-`L` shortlist in the cached miner. It uses `T` query encoder
passes and `T` dense matrix multiplications over `H`, with zero document encoder
calls during ordinary mining batches. The score computation may be chunked over
cache slots and should accumulate mean/variance in FP32 so all `T` full score
matrices do not need to remain resident simultaneously.

The query embeddings come from the current round's frozen checkpoint. A
document's `T` cached embeddings come from the checkpoint recorded in its
`last_refreshed_step`. Therefore both `s_hat` and `sigma` can be affected by
cache staleness; cached `sigma` is a useful uncertainty proxy, not exact
current-checkpoint posterior uncertainty.

## Initial Defaults And Memory

The first runnable configuration is:

```text
B_doc = 32_000
T = 3
lambda_val = 0.5
mc_dropout_p = 0.3
m = 1
selection_mode = topk
rho_start = 0.5
rho_end = 0.25
max_age_epochs = 2
```

Always run `lambda=0` as the direct mean-score baseline. `lambda=1` is an
ablation, not the assumed correct value. Test `B_doc=100_000` only after the
32k configuration meets the async throughput target.

For 1024-dimensional BF16 BGE-M3 embeddings:

| `B_doc` | `Z_mc`, `T=3` | `Z_mean` | Persistent total |
|---:|---:|---:|---:|
| 32,000 | 187.5 MiB | 62.5 MiB | 250.0 MiB |
| 100,000 | 585.9 MiB | 195.3 MiB | 781.2 MiB |

These figures exclude model weights, metadata, query states, and temporary
score buffers.

## Cache Maintenance Semantics

Async Fast-GRASS should keep cache maintenance close to sequential Fast-GRASS.
The miner runs a sequential-like loop over virtual mining batches and maintains
`H` periodically while it is producing `training_data_N`.

The maintenance budget remains the interval budget:

```text
maintenance_budget_interval =
    round(rho * B_doc * cache_update_interval / steps_per_epoch)
```

`cache_update_interval` keeps the same meaning as sequential Fast-GRASS: a
trainer-step-equivalent interval, so the maintenance budget formula above is
unchanged. Because the miner processes query examples rather than optimizer
steps, only the execution trigger is converted to mined queries (maintain every
`cache_update_interval * trainer_batch_size` examples, e.g. 100 * 64 = 6400, not
every 100):

```text
maintenance_interval_mined_queries =
    cache_update_interval * trainer_batch_size
```

Every `maintenance_interval_mined_queries` examples, the miner runs one bounded
maintenance interval:

```text
fold selected_indicator into utility_ema
update peak_utility_ema, lifetime_selected_count, intervals_since_selected
reset selected_indicator
plan refresh and replacement under maintenance_budget_interval
refresh useful stale docs by recomputing all T embeddings and Z_mean
encode replacement candidates for all T passes exactly once
recertify candidates with the recent query-MC reservoir
insert chosen candidates using the already-computed MC embeddings
continue mining the same training_data_N with the updated H
```

Every refreshed or replaced slot is updated atomically as one logical record:
`docid`, all `T` rows of `Z_mc`, `Z_mean`, utility metadata, and
`last_refreshed_step`. An interval refreshes only the slots selected by the
bounded maintenance policy. All unselected slots retain their existing cached
states.

The recent-query reservoir stores bounded no-grad states shaped conceptually as
`[T, R_query, D]`, plus query IDs for qrel masking. Replacement recertification
uses the same mean-plus-uncertainty score as normal mining. Candidate documents
must not be encoded once for ranking and again for insertion.

This is intentionally closer to sequential Fast-GRASS than a single round-end
maintenance pass. `H` can improve while `training_data_N` is being generated:
early records in a mined dataset may come from an older `H`, while later records
may come from a refreshed/replaced `H`.

If a mining round ends with a partial interval, fold its remaining utility state
and optionally run one final bounded maintenance interval if any selected slots
remain pending:

```text
at round end:
    fold remaining selected_indicator if non-empty
    run one final bounded maintenance interval only if useful pending state exists
    write cache_state_N.pt
```

Use a fixed model-time step for maintenance during a round. Every maintenance
call in the round passes the same value:

```text
maintenance_model_step = source_checkpoint_step

cache age:            age = maintenance_model_step - last_refreshed_step
linear-decay budget:  rho = linear_decay(rho_start, rho_end,
                                          maintenance_model_step / total_steps)
on refresh/replace:   last_refreshed_step := maintenance_model_step
```

The miner uses checkpoint-frozen weights for the full round, so model-time cache
age, rho/progress, refresh, and replacement stay FIXED within the round: they are
based on the checkpoint step, not on a miner-local batch/query counter. Only the
utility state advances between calls. Utility EMA and `intervals_since_selected`
update once per maintenance interval (every `maintenance_interval_mined_queries`
mined examples), while age and rho do not move until the next round adopts a
newer checkpoint. Passing a miner-local counter as the step would corrupt cache
age, the rho/budget schedule, and `last_refreshed_step`, which must represent
trainer-model staleness. `cache_state_N.pt` is the final miner-owned cache state
prepared for the next round.

Record maintenance interval totals in metadata:

```text
cache_update_interval
maintenance_interval_mined_queries
maintenance_budget_interval
num_maintenance_intervals
num_refresh_total
num_replace_total
maintenance_model_step
```

Utility semantics remain interval-based:

```text
selected_indicator[d] = 1 if selected at least once since the last maintenance interval
utility_ema[d] = decay * utility_ema[d] + (1 - decay) * selected_indicator[d]
```

This keeps utility close to the current sequential meaning: selected at least
once within a short interval. A doc selected once in a full dataset and a doc
selected hundreds of times should not collapse into the same single binary
round-level update.

`R`, cache utility, selection history, and cache age live entirely in miner
state. The trainer never reads or mutates them.

### `R_doc` is DEFERRED in the first async implementation

The retired-document registry `R` is **not built in Phase 1**. Cached-MCDP
replacement instead draws its whole candidate pool uniformly from the corpus,
excluding documents already in `H`, and recertifies those candidates against the
query-MC reservoir exactly as described below:

```text
Phase 1:  candidates = uniform corpus sample, excluding H
          -> encode T passes once -> recertify with query-MC g -> insert top-k
deferred: registry admission on eviction, nomination, retention, persistence
```

Consequences that hold everywhere `R` appears in this document:

```text
uniform_candidate_fraction is effectively 1.0 for cached-MCDP
nothing is admitted to R when a slot is evicted
num_R_entries and num_R_candidates_total are reported as 0
the persisted cache state serializes no registry entries
```

The **query-MC reservoir is unaffected** and remains required — it is what
recertification scores candidates against. The existing EMA/sequential registry
code is untouched and still active on that path. Adding `R_doc` later requires a
cache-state schema bump.

The persisted cache state contains CPU tensors and sufficient state for an exact
miner restart:

```text
schema_version
docids
Z_mc[T, B_doc, D] in BF16
Z_mean[B_doc, D] in BF16
utility and selection-history tensors
last_refreshed_step per slot
replacement registry R          # DEFERRED — not serialized in cached_mcdp_v1
NumPy and Torch generator states
T, embedding dimension, dtype, and cache configuration
```

Loading validates the schema, `T`, cache size, and embedding dimension before
moving tensors back to the miner device.

Phase-0 timing must match this design. Miner timing should measure periodic
in-round maintenance, not only one end-of-round maintenance cycle.

Not chosen for the first async implementation:

```text
mine full training_data_N with fixed H
run one large cache maintenance pass at round end
```

This is simpler, but less faithful to sequential Fast-GRASS and less likely to
improve cache quality during a long mining round.

## Trainer Loop

The trainer is a continuous optimizer loop:

```text
load initial_data
for global_step in 1..max_steps:
    maybe swap to newest ready training_data_N
    read next batch from active mined data
    fresh-encode queries
    fresh-encode positives
    fresh-encode mined negatives
    compute contrastive loss
    optimizer step
    scheduler step
    save checkpoint every async_mine_every_steps
```

The trainer must not use `Z_mc`, `Z_mean`, or any miner-produced embeddings in
the loss. It trains only from fresh model encodings of the query, positive, and
mined negative texts, matching sequential Fast-GRASS.

If the miner is late, the trainer keeps using the current mined data. If several
rounds are ready, the trainer swaps to the newest ready round and skips older
ones.

## Checkpoint Validity

Use the ANCE validity pattern:

```text
checkpoint-N/
  model weights
  tokenizer files
  scheduler.pt
  optimizer.pt   # written last, validity flag
```

The miner treats a checkpoint as valid only after `optimizer.pt` exists. This
prevents reading partially written checkpoints.

The trainer should save at the fixed `async_mine_every_steps` cadence. If
the miner takes longer than this interval, the miner should skip intermediate
checkpoints between rounds instead of queueing stale work.

## Metadata And Logs

`mining_meta_N.json` fields: `round_no`, `source_checkpoint`,
`source_checkpoint_step`, `B_doc`, `T`, `m`, `lambda_val`, `selection_mode`,
`async_mine_every_steps`, `cache_update_interval`,
`maintenance_interval_mined_queries`, `maintenance_budget_interval`,
`num_maintenance_intervals`, `maintenance_model_step`, `num_queries`,
`num_refresh_total`, `num_replace_total`, `cache_state_path`, `t_mine_round`,
`queries_per_second`, `mcdp_query_encoder_calls`,
`mcdp_doc_encoder_calls_mining`, `mcdp_doc_encoder_calls_maintenance`,
`mcdp_docs_encoded_maintenance`, `cache_mc_bytes`,
`cache_score_pairs`, and `cache_maintenance_time`.

`mcdp_doc_encoder_calls_mining` must be zero. Separating mining and maintenance
document calls makes regressions to lazy fresh-MCDP visible.

Trainer per-swap log fields: `global_step`, `active_round_no`,
`source_checkpoint_step`, `consume_step`, `async_gap_steps`, `data_age_steps`.
`data_age_steps` increases while the trainer keeps consuming the same round.

### Runtime tuning signals

Log per checkpoint/round to re-tune the fixed `async_mine_every_steps` after the
first run:

```text
async_gap_steps        consume_step - source_checkpoint_step (model-data lag)
data_age_steps         trainer steps on the current round since it went active
rounds_consumed        mined rounds the trainer has swapped into
rounds_skipped         ready rounds skipped because a newer one already existed
checkpoint_write_time  wall time to write one trainer checkpoint
miner_idle_time        miner wall time spent waiting for a newer valid checkpoint
```

Rising gap / `data_age_steps` with `miner_idle_time` near zero means the miner is
the bottleneck: raise `async_mine_every_steps`. Large `rounds_skipped` or
`miner_idle_time` at a near-zero gap means the trainer over-checkpoints: lower it
to cut wasted `checkpoint_write_time`.

## Scientific Status

Supported by prior research:

- MC-dropout uses repeated stochastic forward passes as an approximate Bayesian
  predictive distribution. It supports calculating score variation from
  stochastic query/document states, but does not guarantee calibrated
  uncertainty for dense-retrieval rankings.
- Memory banks and asynchronous dense-retrieval indexes show that cached
  representations can amortize encoder work. They also establish staleness as a
  real source of bias that must be controlled through refresh.

Fast-GRASS hypothesis:

- Reusing `T=3` cached document samples while freshly sampling query states
  preserves enough ranking disagreement to improve hard-negative selection.
- This signal may improve Recall/NDCG over EMA because it measures variation
  across nonlinear dropout passes rather than only a slowly changing
  teacher/student difference. The existing observation that EMA `lambda=1`
  behaves like `lambda=0` motivates the hypothesis but does not prove it.
- Periodic partial refresh is frequent enough to keep the signal useful while
  avoiding document encoder calls in the hot mining loop.

The decisive evidence is empirical: cached-MCDP must beat its own `lambda=0`
baseline and EMA at comparable cache/mining budgets, while a small fresh-MCDP
sample measures how much ranking quality caching loses.

## Failure Modes

- Miner slower than checkpoint cadence: trainer keeps old data; miner finishes its
  round then skips stale checkpoints; `data_age_steps` grows and later consumed
  rounds may have larger `async_gap_steps`.
- Miner output incomplete: no `ready_N` marker, so the trainer does not read the round.
- Cache maintenance too expensive: raise `async_mine_every_steps`; lower `B_doc`/`T`;
  raise `cache_update_interval`; lower `rho_start`/`rho_end` only if over-maintained.
- Cached scoring too expensive: begin with `B_doc=32k, T=3`, use cache-slot
  chunking, and compare `B_doc=100k` only after timing the smaller cache.
- Cache states too stale: increase refresh rate or reduce `max_age_epochs`; do
  not interpret a stale `sigma` as current-checkpoint epistemic uncertainty.
- High-variance irrelevant documents dominate: reduce `lambda_val`; the first
  comparison must include `lambda=0`.
- `T=3` is too noisy: compare `T=5` only after cached-MCDP beats the mean-score
  and EMA baselines at `T=3`.
- EMA requested: defer to a future variant unless trainer checkpoints include EMA teacher weights.

## Test Plan

- Async handoff/unit: latest `ready_N` discovery + stale-round skipping; no partial
  reads before `ready_N`; `async_gap_steps` calculation; maintenance fires every
  configured mined-query interval; maintenance budget uses `maintenance_budget_interval`;
  dataloader swap without optimizer/scheduler reset.
- Cached score unit: synthetic `Z_mc` and query states match an explicit
  mean/population-std calculation; `lambda=0` matches mean-score ranking.
- Miner smoke: cached-MCDP negatives come from `H`; known positives are masked;
  no document encoder call occurs during query mining; `B_doc` remains invariant.
- Maintenance unit: every selected slot updates all `T` states and `Z_mean`
  together; unselected slots remain unchanged; replacement candidates are not
  encoded twice.
- Persistence unit: cache save/reload preserves embeddings, utility, refresh
  timestamps, and RNG state (registry is deferred and not serialized);
  incompatible cache schemas fail clearly.
- Integration smoke: tiny corpus + fake checkpoints; trainer consumes `initial_data` then
  swaps to `training_data_1`; global optimizer step continuous across the swap.
- Cluster acceptance: trainer on GPU 0, miner on GPU 1; no full-corpus ANN rebuild; no
  per-query stale FAISS top-P; logs show `source_checkpoint_step`, `consume_step`,
  `async_gap_steps`, `data_age_steps`; at least one `ready_N` round consumed by the trainer.

## Summary

Async Fast-GRASS is:

```text
ANCE-style checkpoint/ready_N orchestration
+ cached-MCDP scoring over the bounded global cache
+ document MC encodes only during initialization and maintenance
+ trainer-only fresh contrastive loss
+ miner-owned H/R/Z_mc/Z_mean state
```

The core engineering tradeoff is explicit: throughput improves by allowing the
trainer to use mined data and cached document states from older checkpoints.
The logs must expose both the trainer/miner handoff lag and cache refresh age.

Cached-MCDP is a Fast-GRASS hypothesis. MC-dropout supports stochastic
uncertainty estimates, and memory-bank research supports reusing cached
representations, but prior work does not establish that their combination
preserves calibrated current-model uncertainty. It succeeds only if its cheap
ranking signal improves Recall/NDCG enough to justify maintenance cost and
staleness.
